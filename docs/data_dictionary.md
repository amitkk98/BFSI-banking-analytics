# Data Dictionary

## 1. bank_features

The bank dataset contains branch-level financial and geographical information.

| Column Name | Description |
|---|---|
| Branch_ID | Unique identifier assigned to each bank branch |
| City | City where the branch is located |
| Region | Geographical region of the branch |
| Firm_Revenue | Revenue generated by the branch |
| Expenses | Expenses incurred by the branch |
| Profit_Margin | Original profit margin field in the dataset |
| net_Income | Calculated as Firm_Revenue minus Expenses |
| profit_margin_pct | Calculated profit margin percentage |

## 2. Customer_features

The customer dataset contains customer demographic information, banking relationships, and engineered financial metrics.

| Column Name | Description |
|---|---|
| Customer_ID | Unique identifier assigned to each customer |
| Age | Customer age |
| Customer_Type | Customer classification based on the project's segmentation logic |
| City | Customer's associated city |
| Region | Customer's associated region |
| Bank_Name | Name of the associated bank |
| Branch_ID | Identifier of the associated branch |
| Total_Account_Balance | Sum of the latest available balances across customer accounts |
| Current_Investment | Latest available investment amount for the customer |
| Net_Worth | Calculated as Total_Account_Balance plus Current_Investment |
| Transaction_Count | Number of transactions associated with the customer |
| Total_Transaction_Amount | Aggregate transaction amount associated with the customer |
| Last_Transaction_Date | Most recent recorded transaction date |

## 3. transaction_cleaned

The transaction dataset contains account-level and transaction-related financial information.

| Column Name | Description |
|---|---|
| Transaction_ID | Unique identifier for a transaction record |
| Customer_ID | Identifier linking the transaction to a customer |
| Account_Type | Type of customer bank account |
| Total_Balance | Recorded account balance |
| Transaction_Amount | Amount associated with the transaction |
| Investment_Amount | Investment amount recorded in the dataset |
| Investment_Type | Category of investment |
| Transaction_Date | Date associated with the transaction |

## 4. Data Engineering Notes

**Granularity & Primary Keys:** The data model follows a relational star/snowflake structure anchored by unique primary keys across all core tables (`Branch_ID`, `Customer_ID`, and `Transaction_ID`).
**Account & Investment Aggregation:** `Total_Account_Balance` was engineered by summing the latest available balance per `(Customer_ID, Account_Type)` pair, while `Current_Investment` reflects each customer's most recent recorded investment position.
**Wealth & Activity Metrics:** Customer `Net_Worth` was derived as `Total_Account_Balance + Current_Investment`, alongside behavioral activity features (`Transaction_Count`, `Total_Transaction_Amount`, and `Last_Transaction_Date`) aggregated from historical transaction records.
**Data Hygiene & Standardization:** Missing values, duplicate records, and date formats were standardized during the Python preprocessing pipeline (`BFSI_Project.ipynb` and `Feature engineering.ipynb`) prior to PostgreSQL ingestion and Power BI modeling.
